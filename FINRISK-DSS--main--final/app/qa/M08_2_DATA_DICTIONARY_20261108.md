# M08.2 — Data dictionary (proposal)

## `app_users`

| Column | Type | Meaning / constraint |
|---|---|---|
| user_id | UUID PK | Internal user key generated by trusted app/auth layer |
| identity_provider | varchar(120) | Trusted identity provider issuer |
| identity_subject | varchar(255) | Stable external subject; unique with provider |
| display_name | varchar(120) | Display-only label; no email/phone/password |
| account_status | ACTIVE/DISABLED | Access status |
| created_at / updated_at | timestamptz | UTC timestamps |

## `app_roles` / `app_user_roles`

Role codes: `VIEWER`, `LOAN_OFFICER`, `REVIEWER`, `AUDITOR`, `ADMIN`, `QA`. Assignments are versioned by `granted_at`/`revoked_at`; only one active assignment per user/role. The database roles (`finrisk_app`, `finrisk_migrator`, etc.) are separate from application roles.

## `loan_applications`

| Column | Type | Meaning / constraint |
|---|---|---|
| application_id | UUID PK | Internal application ID |
| application_code | varchar(40) UNIQUE | Human-friendly app code generated by API |
| owner_user_id | UUID FK | Record owner; API derives from auth |
| applicant_reference | varchar(30) | Form `customer_id`; not CORE4 ID |
| applicant_name_ciphertext | bytea | Application-layer AES-256-GCM envelope only; no plaintext column. Proposed encoding: 12-byte nonce + ciphertext + 16-byte authentication tag (minimum 29 bytes for a non-empty UTF-8 name). |
| pii_ciphertext_format | varchar(32) | Versioned envelope format (`AES_GCM_V1`) |
| pii_key_version | varchar(80) | External key reference/version; key material is never stored in PostgreSQL or source control |
| applicant_age_years | smallint | Declared age, data attribute only |
| monthly_income_amount | numeric(18,2) | VND as labelled in current form |
| monthly_expenses_amount | numeric(18,2) | VND as labelled in current form |
| existing_monthly_debt_amount | numeric(18,2) | VND as labelled in current form |
| requested_amount | numeric(18,2) | Requested, not approved, amount |
| requested_term_months | smallint | Requested, not approved, term |
| loan_purpose_code | varchar(24) | Enumerated current UI purpose |
| currency_code | varchar(3) | ISO-like code; current UI defaults VND |
| application_status | varchar(20) | DRAFT/SUBMITTED/WITHDRAWN/CLOSED only; no APPROVED/REJECTED |
| source_schema_version | varchar(80) | Data-contract version |
| row_version | integer | Optimistic concurrency token |
| created_by / updated_by | UUID FK | Authenticated actor |
| created_at / updated_at / deleted_at | timestamptz | Lifecycle timestamps; soft delete only |

## `financial_validation_runs` / `financial_validation_findings`

Technical/input-quality only. Runs carry validator version, `INPUT_QUALITY` scope, PASS/WARN/FAIL, counts and actor. Findings carry `rule_code`, severity, field path and message key/arguments. No credit policy flag may be true.

## `loan_simulation_scenarios`

Stores only explicitly saved W04 calculations: principal, annual-rate assumption, term, `ANNUITY` or `EQUAL_PRINCIPAL`, currency, formula version, result snapshot and `scenario_only=true`. It is never an approved quote or input to H16.

## `assessment_runs`

Stores successful H18 support output only: `sk_id_curr`, source/data version, feature-set version and count=169, model version/hash, threshold-policy version/value, risk score, `MANUAL_REVIEW_RECOMMENDED` or `NO_REVIEW_SIGNAL`, `business_policy_status=NOT_APPROVED`, `automatic_credit_decision=false`, request ID and sanitized explanation snapshot. No raw 169 features, TARGET, approve/reject or loan-term columns.

## `report_records`

Stores explicit W06 report snapshots, report schema version, link to `assessment_runs`, allowlisted JSON payload, checksum, creator and ACTIVE/ARCHIVED lifecycle. Forbidden exact keys are blocked recursively by a database check function in the draft SQL.

## `audit_events`

Append-only actor/action/entity/request/time and safe metadata. No raw request bodies, credentials, PII or feature vectors. Normal app role gets INSERT and SELECT under actor scope, but no UPDATE/DELETE/TRUNCATE.

## `business_rule_registry`

Rule code/version, title/description, owner, approver reference, status, evidence and timestamps. The proposed check constraint allows only DRAFT/NOT_APPROVED/RETIRED, forces `is_executable=false`, and keeps `approved_at=NULL`. M08.5 may not relax these checks without a separately approved governance change. Runtime grants are SELECT-only for this table in M08.2.

## `schema_migrations`

Migration version, name, SHA-256 checksum, actor and timestamp. App runtime role receives no access.
