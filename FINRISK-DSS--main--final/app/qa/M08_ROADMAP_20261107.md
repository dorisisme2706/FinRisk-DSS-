Move the W01-W07 local academic prototype toward a more consistent application by making REAL/MOCK boundaries explicit, introducing governed app-owned persistence, and completing the remaining product workflows without altering the frozen H16 model.

## Proposed app-owned records (design candidates, not approved schema)

- `loan_application`: user-owned form submissions/drafts. A record must carry owner, schema version and lifecycle status. It is not an H16 input until a separate 169-feature construction contract is approved.
- `simulation_scenario`: optional user-saved W04 hypothetical assumptions and generated schedule. Keep it explicitly separate from the risk score and real loan terms.
- `assessment_run`: immutable reference to a profile ID, model/data/feature/threshold versions, risk score and review signal. It should record that it is a support signal and business policy `NOT_APPROVED`.
- `report_record`: report ID, source profile ID, assessment reference, report schema/version, creator, timestamp and retention status. Decide whether to store a sanitized snapshot or regenerate from immutable references before implementation.
- `audit_event`: actor, action, target type/id, timestamp, request correlation ID and safe metadata. Never store passwords, tokens or unnecessary raw feature vectors in the event payload.

These names are design candidates only. They require review before SQL migrations are authored.

## Technical direction

- PostgreSQL stores application-owned records and workflow metadata; it does not automatically replace the canonical read-only CORE4 Parquet inference path.
- Use environment variables or a local untracked `.env` for connection settings; no passwords or service tokens in Git.
- Use versioned migrations with an explicit upgrade path and documented backup/restore procedure.
- Add authentication and authorization before exposing user-owned records beyond localhost. The current server has no such mechanism.
- Keep W06 browser history as a clearly labelled local option during migration; do not imply it is centralized.
- Keep W04 as hypothetical arithmetic, not an approved rate or offer.
- Keep business-policy implementation blocked until a formal rule owner and approver supply approved rules.
- Dataiku is out of scope and must not be introduced.
